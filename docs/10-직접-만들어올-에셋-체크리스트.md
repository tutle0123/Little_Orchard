# 직접 만들어올 에셋 체크리스트

## 기준과 용도

사용자가 GPT 이미지로 직접 만들어 가져오고, Codex가 적용·구현하는 작업을 위한 목록이다. 지금은 새 이미지를 더 생성하지 않는다.

**승인된 주 기준:** [한 알짜리 블루베리](../art/generated/v3/blueberry-icon-single.png). 밝고 선명한 색, 둥글고 통통한 형태, 매끈한 광택, 간결하고 부드러운 입체 명암. 이전 18장과 블루베리 수정 실험은 새로 제작할 기준에서 제외하고 기록으로만 보존한다. 기존 블루베리 식물 두 상태도 최종 승인된 것으로 간주하지 않는다.

- 그림체: 캐주얼 2D 게임 일러스트. 네이티브 픽셀 격자로 제한하지 않는다.
- 작물: 사과·배·귤·복숭아·블루베리·감. 아이템은 각 과일 **한 개**, 블루베리도 **한 알**.
- 시점: 위에서 비스듬히 내려다보는 고정 탑다운. 물체마다 시점이 달라지지 않게.
- 빛: 위쪽 왼편. 과한 광택·사실적 질감·거친 나뭇결·꼬인 뿌리 금지.
- 투명 물체: 한 이미지에 한 물체/동작. 배경 없이 PNG, 가장자리 여백. 바닥과 그림자까지 같이 넣으면 재배치가 어려우므로 그림자는 가급적 분리.
- 배경: 따로 완성 그림으로 만들 수 있으나 클릭/이동/수확할 나무·선반·사람은 배경에 합쳐 그리지 않는다.
- 수확 전후: 좋은 한 장을 먼저 만든 뒤 그 파일을 편집해 열매만 바꾼다. 캔버스·줄기 위치·그림 크기·빛을 유지.
- 이름·가격·수량·설명·한글·로고는 그림에 새기지 않는다. 코드에서 표시.
- 정확한 최종 픽셀 크기, PNG 시트 배치, 충돌·터치 영역은 Codex가 게임 적용 때 조정한다. 원본과 편집용 파일이 있으면 함께 보관.

## D. 과수원 공간

- [ ] 잔디/흙길이 있는 빈 과수원 바닥 배경 한 장 — 16:9 구도 출발점, 작물·사람·선반 없는 상태.
- [ ] 작은 청과점 외관 — 벽/지붕/창문/입구, 붙박이 나무·사람 없음.
- [ ] 청과점 문: 닫힘/열림, 같은 위치.
- [ ] 울타리: 가로/세로/모서리/끝기둥.
- [ ] 출입문/울타리 문: 닫힘/열림.
- [ ] 글자 없는 간판 판.
- [ ] 풀 작은 덩어리2~3종.
- [ ] 꽃 작은 덩어리1~2종.
- [ ] 돌1~2종.

선택: 건물 뒤로 캐릭터가 지나가게 하려면 지붕/전경 가림층을 분리. 고정 배경에 울타리를 포함했다면 같은 울타리를 또 만들지 않아도 되지만, 문처럼 움직이는 부분은 별도 필요하다. 반복 타일 방식은 대안이므로 완성 배경과 풀 타일셋을 둘 다 먼저 만들 필요 없다.

## E. 청과점 실내와 벽면 진열

- [ ] 비어 있는 청과점 실내 배경: 바닥/벽/창문/출입구. 선반·과일·사람을 그려 넣지 않은 상태.
- [ ] **빈 벽면 목재 선반** — 예쁜 다단 진열대, 정면이 보이는 같은 탑다운 시점.
- [ ] 빈 얕은 과일 상자/트레이 — 선반 칸에 올릴 크기.
- [ ] 계산대/카운터.
- [ ] 글자 없는 상품명/가격표 판.
- [ ] 쇼핑 바구니 또는 종이봉투 하나.
- [ ] 보관용 상자/창고 상자 하나.
- [ ] 선택 장식: 작은 화분, 벽등, 시계 각 하나 정도.

선반은 고정 벽면 배치부터 시작한다. 자유 회전을 위한 앞뒤좌우 선반은 후순위다. 선반 옆 물건을 가져오기 쉬운 통로 폭은 게임에서 조정한다.

## F. 과일 진열 — 기본 6종, 필요하면 소량 모습 추가

- [ ] 사과가 보기 좋게 쌓인 진열용 과일 레이어.
- [ ] 배 진열 레이어.
- [ ] 귤 진열 레이어.
- [ ] 복숭아 진열 레이어.
- [ ] 블루베리 진열 레이어 — 이때는 판매용 여러 알/작은 용기가 가능. 가방 아이콘 한 알 규칙과 구분.
- [ ] 감 진열 레이어.

같은 상자 크기/각도에 맞춰 '과일만' 만들면 빈 상자를 재사용할 수 있다. 과일+상자로 만들 경우 상자는6종 모두 같은 디자인/크기여야 한다. 다음 세 상태가 보이면 좋다:

- 품절: 빈 상자 재사용, 새 과일 그림 불필요.
- 조금 남음: 개별 아이콘 배치로 만들거나 과일별 소량 버전 제작.
- 충분함: 위6종 진열 레이어.

가격·수량을 그림에 고정하지 않는다. 과일만 바뀔 때 선반의 나뭇결·각도·빛이 달라지면 안 된다.

## G. 플레이어 한 명

- [ ] 물주기 동작: 필요한 방향별3~4프레임 제안, 기능 채택 시.
- [ ] 과일/상자 들고 서기.
- [ ] 과일/상자 들고 걷기: 실제 운반을 화면에 보여줄 경우.
- [ ] 진열 보충 동작: 수확의 손 뻗기 동작 재사용 가능.

걷기만 먼저 만들어도 이동은 구현할 수 있다. 모든 동작을 한 번에 그릴 필요 없다. 각 프레임은 몸 크기/얼굴/의상/손과 발 개수/발 위치가 일정해야 한다. 좌우 반전은 비대칭 소품을 확인한 뒤 Codex가 처리할 수 있다. 방향마다 새로운 인물로 바뀌면 불합격이다.

## I. UI용 그림 — HTML/CSS 재사용 가능

- [ ] 가방/바구니 아이콘.

- [ ] 설정/소리 켜짐/소리 꺼짐 아이콘.
- [ ] 패널/버튼/아이템 칸/선택 테두리의 공통 디자인 한 벌.

- [ ] 상호작용 선택 표시: 코드 테두리/마커로 대체 가능.

나무 흔들림, 열매가 가방으로 이동, 상품이 통통 튀는 움직임은 코드로 만들 수 있다. 같은 물체가 기울어진 그림을 여러 장 따로 만들 필요 없다.

## 생성할 때 붙일 공통 문장

> 첨부한 한 알짜리 블루베리와 같은 밝고 통통한 캐주얼 2D 게임 일러스트로 [대상] 한 개를 만들어 주세요. 선명한 색, 매끈하고 부드러운 입체 명암, 간결한 형태와 작은 하이라이트를 유지하세요. 과도한 현실 질감/붓질/나뭇결/검은 윤곽선 없이, 위쪽 왼편에서 빛이 오는 같은 시점으로 맞춰 주세요. 배경 투명 PNG, 물체 전체가 프레임 안에 들어오고 가장자리에 여백이 있게, 글자/가격/수량 없이 만들어 주세요.

배경을 만들 때는 마지막 문장의 '배경 투명'을 빼고 '사람과 상호작용 물체가 없는 빈 공간'으로 바꾼다. 한 알 블루베리만으로는 사람 비율과 건물 시점을 모두 정할 수 없으므로 첫 식물/선반/인물 기준이 마음에 들면 해당 분류의 기준으로 함께 첨부한다. 이전 여러 그림체를 기준으로 섞지 않는다.

## 가져올 때

- 원본 PNG를 파일로 보내기. 채팅 화면 캡처나 JPEG 재저장보다 원본이 좋음.
- `사과-열매있음`, `사과-열매없음`처럼 이름으로 용도를 구분.
- 여러 장은 ZIP으로 묶기. 원본과 이전 버전도 보관.
- 비교용 큰 시트와 별개로 개별 물체/프레임 파일을 함께 주면 적용이 쉬움.
- 정확한 시트 합치기·최종 크기·기준점·충돌·터치·게임 동작 연결은 Codex가 맡음.
- 생성한 파일마다 스타일/실루엣/색감/투명 경계/방향·상태 일관성은 Codex도 다시 검수.
