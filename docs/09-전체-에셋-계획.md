# 전체 에셋 요구사항과 확보 현황

작성: 2026-11-09, 한국 시간. 이 문서는 구현 완료 보고가 아니라 제작·검색·검수용 목록이다.

> **최신 그림체:** 사용자가 이전18장의 질감·일관성을 지적하고 밝고 매끈하고 통통한 캐주얼 게임 이미지를 새 기준으로 제시했다. [그림체 기준](../art/STYLE-GUIDE.md)을 우선 따른다. `art/generated/v3/`에는 그 방향의 블루베리3종 시안과 검수 기록이 있다. 이전 묶음과 구분하며 아직 게임에 반영하지 않았다.

> **제작 방향 갱신:** 사용자는 외부 에셋 구매/검색 대신 **GPT 이미지 직접 제작**을 요청했고, 과수6종·과일·선반을 모은 시안의 그림체를 승인했다. `art/reference/orchard-style-approved.png`가 기준이다. 1차로 작물별 수확 전/후 식물과 아이콘 18개를 순차 생성했다. 결과와 검사 기록은 `art/generated/v1/`에 있으며, 고해상도 일러스트 초안으로 네이티브 픽셀 격자 원본은 아니다. 원시 미리보기에서 보인 블루베리 번짐은 실제 알파/브라우저 합성 검사 후 보류를 해제했다. 캔버스와 밑동 정렬, 실제 게임 크기 및 상태 전환 검수는 아직 남았다. 현재 열매 있는/없는 **전체 식물 이미지 쌍**이며 개별 열매 레이어는 미분리다. 아래 외부 팩 조사 기록은 과거 참고 자료로 보존한다.

## 1. 이번 대화에서 정해진 범위

- 작물은 **사과, 배, 귤, 복숭아, 블루베리, 감** 6종. 현재 코드는 사과·배·감 3종이며 나머지는 아직 구현되지 않았다.
- 공간은 과수원과 청과점 2곳. 청과점 진열은 **가게 안 벽면 선반형**을 기준으로 한다. 천막 노점·시장 전체를 기본 구성으로 늘리지 않는다.
- 캐릭터 직접 이동은 기존 기준을 유지한다. 터치로 대상을 선택하는 방식은 대안으로 논의됐고 확정 변경은 아니다.
- 목표 미감은 따뜻하고 세밀한 탑다운 농장 세계. Tiny Farm RPG의 분위기는 참고 후보이며 정식 선택은 아니다.
- 네이티브 픽셀아트와 AI 일러스트 기반 화면을 모두 검토 중이다. 그림체·해상도 전환을 확정하지 않았다.
- 실제 수확 계절은 참고 정보. 계절 제한, 겨울 맵, 작물 사망, 물주기 효과는 미확정이다.

## 2. 우선순위와 증거 기준

- **필수**: 수확 → 이동 → 진열 → 구매 → 코인의 기본 흐름과 읽기 쉬운 화면에 필요.
- **확장**: 물주기/묘목 성장 등 해당 게임 규칙을 결정한 뒤 제작. 목록에 있다는 이유로 새 기능을 확정하지 않는다.
- **후순위**: 계절·날씨·장식 등 현재 첫 버전에 필수는 아닌 것.
- **파일 확인**: 내려받은 그림을 실제 열어봄. 사용권 확인·그림체 적합·게임 적용 완료와는 다른 상태.
- **페이지 확인**: 공식 상품 설명/미리보기만 확인. 해당 파일을 보유하거나 바로 적용할 수 있다는 뜻이 아님.
- **미확보**: 요구사항에 맞는 파일과 이용 조건을 아직 확인하지 못함.

정확한 총 PNG 수는 아직 정하지 않는다. 시트에 프레임을 묶고 열매·그림자·상품을 재사용하면 같은 그림을 중복 제작할 필요가 없다. 상세 항목은 `09-에셋-목록.csv`에서 관리한다.

## 3. 공통 규칙 — 그림을 만들기 전에 필요

| 항목 | 정할 내용 |
|---|---|
| 시점 | 위에서 비스듬히 내려다보는 고정 탑다운. 아이소메트릭과 혼용하지 않음 |
| 비율표 | 사람·나무·블루베리 관목·문·선반을 한 화면에 나란히 놓고 상대 크기 결정 |
| 스타일 기준판 | 색감, 윤곽선 굵기, 하이라이트·그림자, 잎/나무판자의 디테일 밀도 |
| 빛 | 기본 광원 방향과 접지 그림자 통일 |
| 프레임 | 같은 캐릭터/나무의 상태가 바뀌어도 캔버스 크기와 발·밑동 위치 고정 |
| 파일 | 투명 물체 PNG RGBA. 한글 글자·가격·수량·안내 문구는 코드/UI에서 표시 |
| 겹침 | 발·밑동을 기준으로 앞뒤 정렬. 나무 수관/지붕 가림층과 충돌 영역을 별도 설계 |
| 입력 | 물체 전체의 그림 크기와 클릭/터치 영역, 실제 충돌 영역을 구분 |
| 모바일 | 실제 폰 크기로 검수. 세로/가로마다 에셋을 두 벌 제작하는 대신 카메라와 UI 배치를 조정 |

픽셀 방식을 택하면 정사각 격자, 제한된 팔레트, nearest-neighbor 확대, 정수 좌표를 검수한다. 기존 문서의 타일16/캐릭터16×24/나무32×48은 출발점이며 확정치가 아니다. 과일32×32 원본을 실험했지만 이를 모든 월드 물체의 픽셀 크기로 적용하지 않는다.

일러스트 방식을 택하면 동일한 시점·원근·광원·밀도의 크기 기준을 별도로 고정한다. 생성 이미지의 잔가지·손·얼굴·겹침 오류를 검수한다. 이를 진짜 픽셀아트라고 표시하지 않는다.

## 4. 과수원 공간

| 필수 소재 | 상태/연결 조각 | 비고 |
|---|---|---|
| 잔디·흙길 | 바닥, 경계, 모서리, 끝부분 | 타일 방식이면 반복·경계 조합 필요 |
| 나무 밑 흙 | 마른 상태 | 물주기 도입 시 젖은 상태 추가 |
| 울타리·출입구 | 가로/세로, 모서리, 끝기둥, 문 | 통과 위치와 충돌 영역 일치 |
| 청과점 외관 | 벽·지붕·창문·문·간판 | 한 건물 우선. 문을 통한 맵 전환 표시 |
| 과수 배치 구역 | 밑동 기준점·통행로 | 여섯 수종과 플레이어가 겹칠 때 읽기 쉬워야 함 |
| 배경 정리 | 빈 바닥·경계 배경 | 플레이 구역과 장식 구역 구분 |

풀·꽃·돌은 소수로 통일감을 만든다. 연못·강·우물·벤치·가축은 현재 필수로 만들지 않는다. 물주기가 우물 왕복을 요구하는지도 미확정이다.

## 5. 여섯 작물 — 가장 큰 제작 공백

| 작물 | 식물 모습 | 각 작물의 최소 요구 | 주의 |
|---|---|---|---|
| 사과 | 사과나무 | 성목, 수확 가능 열매, 수확 후 모습, 아이템 | 기존 생성 사과들은 미승인 실험작 |
| 배 | 배나무 | 동일 | 한국 둥근 배/서양 배의 최종 외형 미정. 임의 확정 금지 |
| 귤 | 귤나무 | 동일 | 오렌지·감과 잎/열매 모양 구분. 오렌지 팩을 귤 확보로 세지 않음 |
| 복숭아 | 복숭아나무 | 동일 | 분홍빛 열매와 잎 사이에서 수확 상태가 읽혀야 함 |
| 블루베리 | 낮은 관목 | 관목, 익은 송이, 수확 후 모습, 아이템 | 큰 과일나무의 색만 바꾼 그림으로 대체하지 않음 |
| 감 | 감나무 | 동일 | 주황색 몸통과 넓은 꽃받침 등으로 귤과 구분 |

최소 구현은 **성목/관목 6종 + 익은 열매 표현 6종 + 아이템 6종**으로 분리할 수 있다. 수확 후에는 열매 레이어를 제거해 식물 몸체를 재사용한다. 매달린 작은 열매와 가방에서 크게 보는 아이템은 화면 역할이 다르므로 별도 표시 크기를 검수한다.

추가 성장 표현 후보:

- 묘목/어린 관목 → 어린나무 → 성목: 나무를 심어 키우는 규칙을 도입할 때 제작.
- 열매 없음 → 덜 익음 → 익음: 중간 단계가 시간 경과를 이해하는 데 도움이 되는지 검증 후 추가.
- 수확 흔들림·열매 떨어짐: 기존 식물 스프라이트 이동/변형과 별도 열매로 표현 가능.
- 꽃·겨울 앙상한 가지·눈·병충해·죽은 나무는 후순위.

이렇게 분리하면 여섯 작물에 성장×수분×계절×열매 조합을 모두 완성 그림으로 중복 제작하지 않아도 된다. 열매 위치와 레이어 순서는 수종별 데이터로 관리한다.

## 6. 물주기 — 필요한 표현과 미정 규칙

물주기는 사용자 관심 기능이므로 전체 목록에는 포함하지만, 성장 보너스·건조 시간·물 소비·고사 여부는 아직 확정하지 않는다.

- 물뿌리개 도구/아이콘.
- 캐릭터 앞뒤좌우 물주기 동작 또는 일관된 대체 연출.
- 물줄기·물방울·흙에 닿는 작은 효과.
- 마른 흙/젖은 흙. 색 변화는 사과가 아닌 뿌리 주변 흙에 적용.
- 수분 안내는 색만으로 구분하지 않도록 짧은 효과나 표시 보완.
- 젖은 흙 레이어는 여섯 작물에서 재사용. 수종별 젖은 나무 그림 6벌은 필요 없음.

## 7. 청과점 공간과 벽면 선반

| 필수 소재 | 상태/변형 |
|---|---|
| 실내 바닥·벽·문·창문 | 실내 경계, 출입구, 플레이어 이동 공간 |
| 벽면 목재 선반 | 상단/중단/하단 또는 좌/중/우 연결 조각, 기둥·받침 |
| 상품 상자/칸 | 빈 칸, 상품 레이어를 얹을 영역 |
| 여섯 과일 진열 그림 | 각 과일의 빈 상태/소량/충분한 상태가 구분되게 구성 |
| 가격표·상품 표지 | 배경판만 그림으로, 이름·수량·가격은 UI로 |
| 계산대 | 카운터·결제 위치. 복잡한 금전등록기는 필수 아님 |
| 구매 전달물 | 과일 봉투 또는 바구니 중 하나로 시작 |
| 재고/판매 피드백 | 보충 강조, 구매 시 상품 감소, 코인 증가 |

선반의 빈 상태는 공통 한 벌, 과일은 6종 레이어로 시작할 수 있다. 적게/많이 쌓인 모습은 같은 과일의 배치 수로 표현 가능하다. 한 파일에 선반+6종 과일+가격을 전부 그려 넣지 않는다.

기본 배치는 뒤쪽 벽면 선반을 우선한다. 선반을 자유롭게 회전 배치할 기능은 아직 없으므로 앞뒤좌우 선반 4벌을 기본 요구로 늘리지 않는다. 손님/플레이어가 선반 위 과일을 가리지 않는 높이와 통로를 검수한다.

## 8. 플레이어와 손님

| 대상 | 필수 | 확장 후보 |
|---|---|---|
| 플레이어 1명 | 앞·뒤·좌·우 정지와 걷기 | 수확·물주기·운반·보충 전용 동작 |
| 손님 1명 | 같은 방향 규칙의 정지와 걷기 | 외형 1종 추가, 상품 고르는 동작 |
| 공통 | 발밑 그림자, 발 위치, 방향별 기준점 | 손에 든 물체/도구 레이어 |

첫 걷기는 방향당4프레임을 제안한다. 정지프레임을 공유하면 인물당 걷기16프레임이 출발점이다. 이는 실제 팩의 프레임 수를 강제로 바꾸라는 뜻이 아니다.

좌우 반전은 가방·손잡이·헤어 등 비대칭 디자인을 확인한 뒤 사용한다. 손님 진입/대기/구매/퇴장은 게임 상태이며, 각 상태마다 전용 그림이 꼭 필요한 것은 아니다. 구매·관심 표시는 작은 말풍선과 정지 자세로 시작 가능하다.

직접 이동을 없애는 대안을 실제 채택하면 일부 걷기 에셋을 줄일 수 있지만, 현재 계획에서 자동으로 삭제하지 않는다.

## 9. UI·효과·사운드

필수 UI 구성:

- 코인, 가방, 과일6종, 위치/안내, 진열수량, 성장/수확 가능 표시.
- 방향 버튼/조이스틱 중 기존 방식 유지, 상호작용 버튼, 누름/해제/비활성 상태.
- 패널·아이템 칸·선택 테두리·닫기/뒤로·설정/음소거.
- 저장 성공/실패, 재고 없음, 수확 불가, 진열 보충 결과를 전달할 텍스트/표시.
- 처음 사용 안내, 로딩 화면, 세이브 초기화 확인창.

UI는 HTML/CSS와 글자를 활용할 수 있다. 위 항목 모두를 PNG로 만들 필요는 없다. 한글을 AI 그림 안에 넣지 않는다. 이동 불편을 가리는 화면 장식보다 읽기/터치 영역이 우선이다.

효과: 수확 열매 이동, 나뭇잎 흔들림, 상호작용 강조, 진열/구매, 코인 획득. 물주기를 도입하면 물방울 효과 추가. 작은 프레임 시트와 코드 트윈으로 반복 사용한다.

사운드 목록: 수확, 보충, 구매/코인, 버튼, 문, 물주기(해당 기능 구현 시), 가벼운 발소리. 과수원/가게 배경음과 환경음은 후순위. 물품마다 음악이 필요하지 않으며 음악·사운드도 출처/배포 조건 확인이 필요하다.

## 10. 확보·후보·부족분 대조

## 12. 제작/확보 순서와 완료 판단

1. 스타일·비율 기준판: 사람1명, 사과나무, 블루베리 관목, 선반, 과일아이콘, 바닥을 비교.
2. 사과 한 종류로 성목/열매/수확/가방/진열/구매까지 같은 에셋을 실제 연결.
3. 다른5종을 같은 규칙으로 추가. 특히 감·귤·배 외형, 블루베리 크기 검수.
4. 최종 인물 앞뒤좌우·나무뒤 가림·선반앞 통로 검수.
5. 물주기/묘목 성장 규칙을 결정한 항목만 제작·구현.
6. UI·효과·소리 정리 후 PC·폰 세로/가로에서 실제 확인.

새로 제작하는 파일마다 ID, 용도, 원본크기, 프레임수/속도, 기준점, 클릭/충돌 영역, 그림자, 레이어, 출처/사용권, 실제검수 상태를 기록한다. 후보팩을 봤거나 PNG가 열린 것만으로 플레이 검증을 완료했다고 표시하지 않는다.

이 목록 작성 단계에서는 그림체 변경, 신규 게임기능, 에셋 구매/공개 업로드, 기존 저장규격 변경을 수행하지 않는다.
