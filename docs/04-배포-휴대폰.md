# 04. 컴퓨터·휴대폰 접속과 GitHub Pages

## 질문: PC에서 만든 다음 PC를 꺼도 휴대폰으로 플레이할 수 있나요?

**가능합니다.** 다만 PC에서만 켜 두는 개발 서버가 아니라 **GitHub Pages처럼 항상 접속 가능한 호스팅에 배포**한 경우에만 해당합니다.

| 방식 | 컴퓨터 OFF 상태에서 휴대폰 접속 | 인터넷 |
|---|---|---|
| `npm run dev` 개발 서버를 같은 Wi-Fi에서 열기 | 불가 | LAN 필요 |
| GitHub Pages 웹사이트 | 가능 | 기본적으로 필요 |
| 향후 네이티브/웹뷰 앱 설치 | 가능 | 게임 구성에 따라 다름 |
| 설치형 PWA + 오프라인 캐시 | 추가 구현 후 가능 | 최초 다운로드/업데이트 때 필요 |

**주의:** GitHub에 코드만 올리면 자동으로 게임 URL이 생기는 것은 아닙니다. **Pages 배포를 활성화**해야 합니다.

## 최초 배포 절차

1. GitHub 저장소에 파일을 업로드하고 `main`으로 커밋합니다.
2. `npm install`을 해서 **`package-lock.json` 생성 및 커밋**(코딩 환경에서 수행).
3. GitHub 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions** 선택.
4. `main` 푸시 시 `.github/workflows/deploy.yml`이 잠금 파일이 있으면 `npm ci`(없다면 `npm install`) → `npm run test` → `npm run build` → `dist/` 업로드를 실행합니다.
5. GitHub **Actions** 탭에서 성공 여부 확인. **Settings → Pages**의 방문 URL을 확인합니다.
6. PC, 모바일 브라우저에서 해당 URL 접속하여 이동·터치·가게 기능을 확인합니다.
7. 배포에 실패하면 Actions 실행 로그를 먼저 확인하세요.

배포 URL 예: `https://계정명.github.io/little-orchard/`. GitHub Pages 프로젝트 사이트는 저장소 이름 경로를 사용합니다. 이 스타터의 Actions는 자동으로 해당 base 경로를 설정합니다.

## 자주 하는 실수

- `main`이 아닌 다른 브랜치에서 파일만 변경해 두고 '왜 배포되지 않지?'
- GitHub Pages의 Source를 브랜치 배포로 설정해 놓음 (여기는 Actions 방식)
- 빌드 결과물이 아닌 소스 폴더를 그대로 배포
- `package-lock.json` 없이 `npm ci` 실행
- `assets` 경로를 절대 `/assets/`로 고정해 저장소 경로에서 이미지가 사라짐
- 모바일에서 브라우저 주소창/하단 제스처 영역 때문에 버튼이 가려짐
- PC 세이브가 폰에서도 자동으로 공유될 거라고 생각함

## PC와 모바일 플레이 차이

- 동일한 웹게임 주소와 코드 사용 가능
- **localStorage는 브라우저/기기/도메인별로 분리**됨. PC에서 과일 20개를 모아도 폰에서 보이지 않습니다.
- 브라우저 캐시/사이트 데이터 삭제·시크릿 모드·일부 브라우저 정책으로 저장이 사라질 수 있습니다.
- 포털/메신저 내부 브라우저보다 Chrome/Safari 등 일반 브라우저 테스트가 좋습니다.
- **웹 링크는 곧 앱스토어 설치 앱이 아닙니다.** 나중에 앱으로 만들 때 Capacitor 또는 엔진/플랫폼 변경을 별도로 결정합니다.

## 출시 전 꼭 확인

호스팅 주소 변경 때 저장소(origin)가 바뀌면 기존 세이브가 안 보일 수 있습니다. 방문자에게 중요한 저장 데이터가 쌓이기 전에 저장 내보내기 기능을 검토하세요.

## 공개 범위 주의

GitHub Pages가 배포되면 사이트는 일반적으로 공개됩니다. 비공개 플레이를 원하는 경우 바로 Pages를 열지 말고 개발 서버 및 제한된 테스트 방법을 선택해야 합니다. Pages 요금제/공개 정책은 공식 문서를 확인하세요.
