# 02. 코드 구조와 분리 규칙

목표는 개발하면서 덜 꼬이고, 새 작물을 추가할 때 엉뚱한 기능이 망가지지 않게 만드는 것입니다.

```text
little-orchard-project/
├─ README.md                 # 전체 안내
├─ START-CODEX.md            # AI 코딩 도구 첫 요청
├─ AGENTS.md                 # AI 작업 규칙
├─ CHANGELOG.md              # 버전별 기능·수정 기록
├─ package.json              # 설치와 실행 명령
├─ vite.config.js            # 웹 빌드 경로
├─ index.html                # 게임 입구
├─ src/
│  ├─ main.js                # Phaser 진입점
│  ├─ style.css              # 페이지/화면 크기/UI
│  ├─ game/
│  │  ├─ data/fruits.js      # 과일명·가격·재성장 시간
│  │  ├─ logic/economy.js    # 수확/재고/판매 순수 로직
│  │  ├─ logic/save.js       # 저장 데이터 버전/검증/로딩
│  │  ├─ art/makeSprites.js  # 기술 데모용 픽셀 스프라이트
│  │  └─ scenes/
│  │     ├─ OrchardScene.js  # 과수원 화면/이동
│  │     └─ MarketScene.js   # 청과점 화면/이동
│  └─ ui/controls.js         # 모바일 버튼 + 키보드 보조
├─ tests/                    # 순수 로직 자동검사
├─ docs/                     # 기획·배포·시험·아트 기준
└─ .github/workflows/        # 자동 테스트·배포
```

## 반드시 지킬 코드 분리

- **데이터**: 이름/가격/시간/초기 재고 등은 `data/`에만.
- **게임 규칙**: 과일 수확/판매/잔고 확인/재고 등은 `logic/`에만. Phaser 객체나 DOM에 의존하지 않도록.
- **씬**: 나무나 캐릭터를 화면에 그리기, 이동 감지, 상호작용 연출만.
- **UI**: 터치 버튼, 안내 텍스트, HUD 등 화면 입력 담당. 경제 규칙을 직접 계산하지 않음.
- **저장**: 데이터에 `schemaVersion`을 넣고 검증·마이그레이션 준비. 업데이트에서 과거 세이브를 조용히 삭제하지 않음.
- **아트**: 고해상도 AI 이미지 끼워 넣지 않음. 네이티브 픽셀 격자/스프라이트 시트로 제작. 에셋 라이선스 기록.

## 바꾸는 작업 예시

- 사과 가격 변경 → `fruits.js`만 조정 + 가격 계산 테스트.
- 감나무 픽셀 그림 변경 → `art/` 또는 `assets/`만.
- 손님 추가 → 경제 판매 규칙 유지, NPC 행동 및 스프라이트만 추가.
- 새 휴대폰 버튼 → `ui/controls.js`와 `style.css`만.
- 코딩 AI가 파일 전체를 무턱대고 갈아엎지 못하도록 `AGENTS.md`가 지침 제공.

## 추후 추가 권장 폴더

`public/assets/tiles/`, `public/assets/sprites/`, `public/assets/audio/`, `src/game/npc/`는 **실제로 해당 기능을 만들 때** 추가합니다. 비어 있는 추상적인 파일을 수십 개 만드는 건 지양합니다.

## 기본 저장 데이터 예

```json
{
  "schemaVersion": 1,
  "coins": 0,
  "inventory": { "apple": 0, "pear": 0, "persimmon": 0 },
  "shelf": { "apple": 0, "pear": 0, "persimmon": 0 },
  "trees": [
    { "id": "tree-apple-1", "fruit": "apple", "nextReadyAt": 0 }
  ],
  "location": "orchard"
}
```

저장 시간을 기기 로컬 시각에 의존시키면 시계 변경의 영향을 받을 수 있습니다. 최초 단순 게임에서는 수용하되 재성장 시간 검증 규칙을 둡니다.
