# 00. 처음 시작하시는 분을 위한 안내

이 문서는 **처음부터 게임을 완성해야 한다는 압박 없이, 작은 게임을 오래 안전하게 키우는 절차**를 설명합니다.

## 필요한 것

- GitHub 계정 / Codex 또는 Claude Code 등의 코딩 환경
- PC에서 직접 실행할 경우 Node.js(최신 LTS 권장), Git(또는 GitHub Desktop), 코드 편집기
- 폰은 **게임 확인용**으로 사용: GitHub Pages 배포 후 링크 열기
- **Godot은 설치하지 않습니다.** 현재는 HTML5 + Phaser 게임을 만들기로 결정했습니다.

## 처음 만드는 순서

1. GitHub에 `little-orchard` 등 원하는 이름의 **새 저장소** 생성. 처음엔 README 없이 빈 저장소가 편합니다.
2. ZIP을 압축 해제하고 **그 안의 파일·폴더를 통째로** 저장소에 넣기. `.github` 같이 점(.)으로 시작하는 폴더를 빠뜨리지 마세요.
3. 작업 중인 PC 또는 Codex 환경에서 `npm install` → `npm run test` → `npm run build` 확인.
4. `package-lock.json`을 포함해 첫 커밋을 저장. 예: `chore: initialize orchard project`.
5. `START-CODEX.md` 내용을 Codex에 전달. 첫 작업은 **기능 추가보다 실행·빌드 확인**입니다.
6. 작은 기능마다 별도 브랜치에서 작업 → 확인 후 `main`에 합치기.
7. 다른 사람도 폰에서 플레이해 보고 싶어지면 GitHub Settings → Pages에서 **GitHub Actions** 선택.
8. 기능이 잘 동작하는 시점을 `v0.1.0` 같은 태그/Release로 기록.

## 아주 쉽게 비유하면

- **폴더 구조** = 가게의 서랍을 나누는 것(재고·손님·결제 규칙이 섞이지 않도록)
- **커밋(commit)** = 수시로 찍는 복구용 사진
- **브랜치(branch)** = 망가져도 본 게임은 안전한 연습 공간
- **PR(pull request)** = 연습한 변경을 본 게임에 반영하기 전에 점검하는 절차
- **태그(tag)/Release** = `v0.1.0`처럼 보관하는 중요한 완성 지점
- **Actions** = 코드 검사·배포를 대신 수행하는 GitHub 자동화
- **Pages** = 내 PC가 꺼져도 사이트를 보여주는 호스팅
- **게임 저장 데이터** = GitHub 코드 저장과 전혀 다른 것! 게임은 기기 브라우저에 따로 저장됩니다.

## 처음에 지나치게 만들지 말 것

멀티플레이, 서버, 수십 명의 주민, 장대한 맵, 제작/요리, 계절 등을 **처음부터 설계에 과하게 넣지 않습니다**. 기능을 늘리고 싶을 때 `docs/01-게임-기획.md`와 `CHANGELOG.md`를 먼저 수정합니다.

## 유의할 점

이 프로젝트의 기본 아트는 기능 검증용 픽셀 그림입니다. 처음 보여주신 고품질 레퍼런스처럼 보기 좋게 만들기 위해선 **별도 타일셋/스프라이트 제작과 반복 검수**가 필요합니다. 코드가 실행된다는 사실과 그래픽이 완성됐다는 사실은 다릅니다.
