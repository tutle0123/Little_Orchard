# 01. 작은 과수원과 청과점 — 게임 기획서 v0.1

## 1) 한 줄 콘셉트

작은 과수원에서 **사과·배·감**을 직접 따고, 자기 **청과점**에 진열하여 손님에게 판매하고, 수익으로 나무와 가게를 천천히 가꾸는 아기자기한 **탑다운 픽셀아트 싱글플레이 웹게임**.

## 2) 이미 정한 사항 (가급적 유지)

- PC와 휴대폰 브라우저 양쪽에서 플레이 가능한 웹게임부터 만든다.
- 재미있으면 콘텐츠를 추가하고 나중에 모바일 앱으로 전환한다.
- 플레이어 캐릭터를 직접 이동한다. 키보드와 터치 입력 지원.
- 공간은 **작은 과수원 + 작은 청과점** 2곳으로 시작한다.
- 과일은 **사과, 배, 감** 3종. 실질적 콘텐츠가 적어도 조작·기본 재미·그래픽에 집중한다.
- 기본 순환: **이동 → 수확 → 가게로 이동 → 진열 → 손님 구매 → 코인 → 확장/반복**.
- AI로 만든 픽셀풍 이미지를 실제 픽셀 스프라이트인 것처럼 사용하지 않는다.
- 일관된 네이티브 픽셀 규격과 애니메이션이 있는 화면을 지향한다.
- 계정·서버·광고·결제·멀티플레이 없음. 저장은 첫 버전에서 해당 브라우저에 로컬로만.
- 코드·데이터·씬·UI 분리, Git 버전 관리, Pages 자동 배포 가능 구조.

## 3) 임시 설정값 (테스트하면서 조정)

| 과일 | 초기 진열 판매가(코인/개) | 다음 열매까지 | 초기 상태 |
|---|---:|---:|---|
| 사과 | 6 | 30초 | 성숙한 나무 1그루 |
| 배 | 8 | 40초 | 성숙한 나무 1그루 |
| 감 | 10 | 50초 | 성숙한 나무 1그루 |

숫자는 게임 밸런스 확정이 아닌 **테스트 가값**입니다. 코드에 흩뿌리지 않고 `src/game/data/fruits.js`에서 관리합니다. 나무는 매번 새로 심는 방식이 아니라 일정 시간 후 다시 열리는 과수 시스템입니다. 매 시점 1그루당 수확량은 우선 1개로 단순화하고 나중에 바꿀 수 있습니다.

## 4) 최초 출시 목표(작고 완성된 게임)

**과수원**: 3종 나무, 수확 상태 변화, 직접 이동, 상호작용, 간단한 길·울타리·나무 배경.

**청과점**: 3종 진열 슬롯, 플레이어 직접 보충, 손님 입장→진열대 이동→구매→퇴장, 돈 획득 피드백. 처음에는 방문 손님 종류가 1~2종이어도 괜찮음.

**경제**: 인벤토리, 판매 수익, 간단한 묘목/장식 구매, 과수원 확장 1단계(재미가 충분할 때).

**편의**: 키보드와 터치, 사운드 토글, 저장/이어하기, 모바일 화면이 잘리지 않는 UI, 첫 실행 사용법 3줄.

**완료 기준**: 시작부터 수확→이동→진열→판매→코인→다음 수확까지 **한 사이클이 오류 없이 작동**하고, 폰과 PC에서 모두 조작 가능.

## 5) 의도적으로 안 만드는 기능

복잡한 마을, NPC 관계·대화, 계절, 날씨, 요리, 낚시, 농사 20종, 멀티플레이, 로그인, 광고, 클라우드 동기화, 전용 모바일 앱 빌드. **재미가 확인되면 확장 후보로만 기록**합니다.

## 6) 향후 확장 방식

- 과일 추가: `fruits.js`의 데이터 + 아트 + 테스트만 추가, 기존 시스템 수정 최소화
- 새 맵: `src/game/scenes/`에 씬 추가, 이동 경로 별도 정의
- NPC: `src/game/logic/` 행동 규칙과 `scenes/` 화면 표현을 분리
- 가게 장식: 구매 데이터·배치 렌더링 분리
- 앱화: 웹게임을 Capacitor 같은 웹앱 래퍼로 패키징하는 방법을 **그때 검토**, 모바일 조작/저장/성능 재검증

## 7) 아직 정하지 않은 사항

캐릭터의 구체적인 외형, 정식 타일셋 팔레트, 사운드, 가게 이름, 상점의 추가 목표, 과일 수확량, 최종 경제 밸런스. Codex가 멋대로 확정하면 안 됩니다. 임시값은 명시해 기록하세요.

## 8) 출시 전 핵심 질문

플레이어는 수확과 진열에 의미 있는 선택을 하는가? 손님의 방문·판매가 적절히 보상감을 주는가? 10분 플레이 후 반복하고 싶은가? 답이 아니라면 새 콘텐츠보다 **기존 반복의 재미와 피드백**을 개선합니다.
